fleetd
https://fleetd.sh

fleetd runs Claude Code on your machines: you type what you want, and it plans
the work, runs the agents, opens pull requests it has checked, and asks you only
about real decisions.

An agent saying "done" doesn't merge anything. Every change goes through
fleetd's merge train: reviewed, rebased onto main, merged only on green CI.

Install
  curl -fsSL https://fleetd.sh | sh
  Installs and sets up fleetd: about a minute later the hub runs, the app is
  paired, and you type your first order. You need macOS or Linux x64, the
  claude CLI logged in (your own claude setup, proxy included), git and gh.
  MIT.

Docs:   https://fleetd.sh/docs
GitHub: https://github.com/unlaboredlabs/fleetd

WHAT THE LEAD DOES WITHOUT ASKING YOU
01  The lead decides everything that isn't a product, money, credential or irreversible call.
02  The lead files the rest with `fleetd ask`, each with a class, a recommendation
    and what it blocks, and carries on without waiting.
03  The lead hands workstreams and tasks to Claude Code agents on your machines.
04  The lead starts every wake from the hub's digest: answers, open workstreams,
    tasks, open asks, decisions.
05  The lead doesn't re-ask a key that's already decided.
06  The lead keeps your answer when it overrides its own recommendation.
07  The lead gets an incident, I1 misfiled_ask, when you drop an ask it could
    have decided itself.

SETUP IS A HUB AND YOUR MACHINES
After the install, `fleetd init` walks you through the hub, its claude and gh
logins and the desktop app's pairing. `fleetd machine add` turns a machine you
can reach over SSH into one that runs agents. Both outputs are real; the tailnet
name and address are placeholders.

The hub, on the machine you installed on. --yes takes every default;
--no-service keeps this capture from starting a service, so here the hub, your
workers, a first project and `fleetd doctor` wait for you:

A worker. --dry-run prints the plan and runs nothing; the shell command under
each step is left out here:

$ fleetd machine add builder-1 --dry-run
dry run: nothing runs. Planned for a fresh Linux machine at builder-1 (home /home/demo); a real run first reads the machine's state and leaves out what is already done:
[probe] read the machine's state (read-only)
[1/5] create fleetd's directories
[2/5] install fleetd 0.0.0
[3/5] write the node service
[4/5] enroll the node with a one-time token (sent on stdin)
[5/5] (re)start the node
[hub] wait until builder-1 is online
[exit 0]
