fleetd
https://fleetd.sh

fleetd runs Claude Code on your machines. You type what you want, and it plans
the work, runs the agents, opens pull requests it has checked, and asks you only
about real decisions.

Install
  curl -fsSL https://fleetd.sh | sh
  Installs the fleetd CLI and desktop app, then runs `fleetd init` to set up the
  hub and pair the app. You need macOS or Linux x64, the claude CLI logged in
  (fleetd uses your own claude setup, including any proxy), git, and gh for
  pull requests. MIT.

Docs:   https://fleetd.sh/docs
GitHub: https://github.com/unlaboredlabs/fleetd


ONE CHAT PER PROJECT
Tell the lead what you want; it splits the work and runs the agents. The panel
beside the chat shows what each agent is doing now. Image: chat-hero.png


WHAT FLEETD DOES
A hub keeps your projects, a node on each of your machines runs the agents, and
the desktop app is where you talk to them.

Chat with the lead
  Each project has one lead. It decides everything that isn't a product, money,
  credential or irreversible call, asks you the rest in the chat, and logs each
  answer as a decision. https://fleetd.sh/docs/chat

Agents and the merge train
  Writers open pull requests and reviewers check them. Only fleetd merges: each
  PR is reviewed, rebased onto its base branch and merged on green CI.
  https://fleetd.sh/docs/merge-train

The panel
  Beside each chat, a tab each for the project's Agents, PRs, Checklist, Train,
  Activity and Decisions. Watch an agent work, read a PR's changes, see what
  merges next. https://fleetd.sh/docs/desktop-app#panel

Project settings and env vars
  Environment variables every agent of a project gets, plain or secret. A
  secret lives only on the project's machine and is masked in agents' output.
  https://fleetd.sh/docs/projects#env

Automations
  A stored prompt that runs on a schedule, from a webhook, or with Run now. Each
  run becomes work the lead starts on its own. https://fleetd.sh/docs/automations

Skills
  SKILL.md workflows from the repo, the project or the whole hub, for every
  agent. skills.sh and Claude Code skills work as they are.
  https://fleetd.sh/docs/skills

MCP servers
  More tools for agents: a command on their machine or a service over HTTP, for
  every project or one, with a choice of which roles get each.
  https://fleetd.sh/docs/mcp-servers

Memory
  When you correct the lead or state a rule, it remembers, for you everywhere or
  for one project. Read, edit or delete it in Settings -> Memory.
  https://fleetd.sh/docs/what-agents-are-told#memory

Usage limits
  An agent that hits a Claude usage limit pauses and carries on by itself at the
  reset. A machine near the end of a usage window takes no new agents until it
  has room. https://fleetd.sh/docs/machines#guard


WHAT WAITS FOR YOU
Plain chat can't carry two things safely, so they show as items in the chat
that only your app can act on.

Approve what can't be undone. A command that can't be undone, costs money or
needs a credential waits, exactly as it will run, until you approve it.
Image: chat-approve.png

  Lead: This writes to the production database. Approve to run it exactly as below.
  Command                                                     Can't be undone
  Adds the share snapshots table to the production database.
    pnpm --filter storefront db:migrate --env production
  on devbox in /home/dev/src/storefront · stops after 10 min
  DATABASE_URL gets the secret storefront.database_url
  [Approve]  [Deny]

Secrets stay out of the chat. You type a key into a masked field. It is sealed
to the machine that uses it; the chat and the hub never see it.
Image: chat-secret.png

  Lead: Need the Stripe test key for that. It goes to devbox only and never into this chat.
  Secret                                                      stripe.test_key
  The checkout tests charge a test card; they need the Stripe test key.
  It is saved as STRIPE_TEST_KEY in /home/dev/src/storefront/.env.test on devbox.
  [Paste or type the value]  [Save secret]
  Sealed on this computer to devbox's key, so only devbox can open it. fleetd never shows it again. To skip it, say so in the chat.

GET STARTED
A hub on one machine, and any machines you reach over SSH to run agents. The
outputs below are real; the tailnet name and address are placeholders.

1  Run the install line
   It installs fleetd and starts `fleetd init`, which walks you through the
   hub, its claude and gh logins and the desktop app's pairing. Run it again any
   time; it keeps what's done.

2  fleetd machine add
   Turns a machine you can reach over SSH into one that runs agents. --dry-run
   prints the plan and runs nothing.

$ fleetd machine add builder-1 --dry-run
dry run: nothing runs. Planned for a fresh Linux machine at builder-1 (home /home/demo); a real run first reads the machine's state and leaves out what is already done:
[probe] read the machine's state (read-only)
[1/5] create fleetd's directories
[2/5] install fleetd 0.0.0
[3/5] write the node service
[4/5] enroll the node with a one-time token (sent on stdin)
[5/5] (re)start the node
[hub] wait until builder-1 is online
[exit 0]

3  Add a project and say hi to its lead
   In the app, click Add next to Projects and paste a GitHub URL. Then tell the
   lead what you want.
