fleetd runs Claude Code on your machines.

You type what you want, and it plans the work, runs the agents, opens pull requests it has checked, and asks you only about real decisions.

curl -fsSL https://fleetd.sh | sh

Installs the fleetd CLI and desktop app, then runs fleetd init to set up the hub and pair the app. You need macOS or Linux x64, the claude CLI logged in (fleetd uses your own claude setup, including any proxy), git, and gh for pull requests. MIT.

What fleetd does

A hub keeps your projects, a node on each of your machines runs the agents, and the desktop app is where you talk to them.

  • Chat with the lead

    Each project has one lead. It decides everything that isn’t a product, money, credential or irreversible call, asks you the rest in the chat, and logs each answer as a decision.

    Chat with the lead

  • Agents and the merge train

    Writers open pull requests and reviewers check them. Only fleetd merges: each PR is reviewed, rebased onto its base branch and merged on green CI.

    Merge train

  • The panel

    Beside each chat, a tab each for the project’s Agents, Pull requests, Train, Checklist, Activity and Decisions. Watch an agent work, read a PR’s changes, see what merges next.

    The desktop app

  • Project settings and env vars

    Environment variables every agent of a project gets, plain or secret. A secret lives only on the project’s machine and is masked in agents’ output.

    Projects

  • Automations

    A stored prompt that runs on a schedule, from a webhook, or with Run now. Each run becomes work the lead starts on its own.

    Automations

  • Skills

    SKILL.md workflows from the repo, the project or the whole hub, for every agent. skills.sh and Claude Code skills work as they are.

    Skills

  • MCP servers

    More tools for agents: a command on their machine or a service over HTTP, for every project or one, with a choice of which roles get each.

    MCP servers

  • Memory

    When you correct the lead or state a rule, it remembers, for you everywhere or for one project. Read, edit or delete it in Settings → Memory.

    Memory

  • Usage limits

    An agent that hits a Claude usage or rate limit pauses, and carries on by itself once it can: at the reset, or when a later check gets through. A machine near the end of a usage window takes no new agents until it has room.

    Machines

Get started

A hub on one machine, and any machines you reach over SSH to run agents. The outputs below are real; the tailnet name and address are placeholders.

  1. Run the install line

    It installs fleetd and starts fleetd init, which walks you through the hub, its claude and gh logins and the desktop app’s pairing. Run it again any time; it keeps what’s done.

  2. fleetd machine add

    Turns a machine you can reach over SSH into one that runs agents. --dry-run prints the plan and runs nothing.

    fleetd machine add --dry-run output 
    $ fleetd machine add builder-1 --dry-run
dry run: nothing runs. Planned for a fresh Linux machine at builder-1 (home /home/demo); a real run first reads the machine's state and leaves out what is already done:

[exit 0]

  3. Add a project and say hi to its lead

    In the app, click Add next to Projects and paste a GitHub URL. Then tell the lead what you want.
