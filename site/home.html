A software factory on your own machines.

fleetd isn’t another coding assistant. You give it work; a lead plans it; agents build in parallel on your machines; a separate reviewer checks every change; a merge train lands it. You’re asked only for decisions.

curl -fsSL https://fleetd.sh | sh

Installs the fleetd CLI and desktop app, then runs fleetd init to set up the hub and pair the app. You need macOS or Linux x64, the claude CLI logged in (fleetd uses your own Claude Code setup, including any proxy), git, and gh for pull requests. Open source, MIT.

The whole line, not one more chat window

A coding assistant waits for you at every step. fleetd runs the steps between your request and a merged pull request, on machines you own, and comes back to you only for the calls that are yours.

  • A lead for each project

    Each project has one lead: a Claude Code session you chat with. It turns what you ask into work, starts agents for it, follows them through review and merge, and tells you when it’s done.

    Chat with the lead

  • Agents in parallel, on your machines

    Writers run Claude Code on the machines you add, over SSH or with a join code. Each gets its own git worktree and branch and opens a pull request. You set how many run at once.

    Machines

  • A merge train that lands it

    Only fleetd merges. It rebases each reviewed PR onto its base branch, waits for every required check on that exact commit, and merges. Red CI or a conflict goes back to the agent that wrote it.

    Merge train

What keeps it trustworthy

Agents do the work; the checks around them don’t depend on any one agent getting it right.

  • A review on every change

    Every pull request gets a fresh reviewer, a separate agent from the one that wrote it. Blocking findings go back to the writer, and a new commit gets a new review.

    Review

  • You approve what can’t be undone

    A command that can’t be undone, costs money or needs a credential waits, exactly as it will run, until you approve it in the app. No agent can approve itself.

    Approvals

  • Secrets stay secret

    You type a secret into a masked field. It is sealed to the one machine that uses it, never reaches the hub in plain text, and is masked in everything agents send back.

    Secrets

  • Decisions stay yours

    The lead asks you only about product calls, money and irreversible steps, as numbered questions in the chat. It decides the rest itself, and logs each of your answers as a decision.

    Reply to the lead

  • Updates that roll back

    One Update button updates the hub, every machine and the app. A new build that doesn’t come up healthy within 90 seconds is put back, and agents carry on where they were.

    Updating

  • Your machines, your login

    The hub and agents run on hardware you choose, with your own Claude Code login, git and GitHub. fleetd is open source under the MIT licence.

    Security

Also in the box

A hub keeps your projects, a node on each machine runs the agents, and the desktop app is where you talk to them and watch the work.

  • Status and Factory

    One row per project: what it’s doing, what waits on you, what merged last. Factory charts what came out: pull requests merged per day, time from request to merge, and your minutes per merged PR.

    Status · Factory’s figures in the terminal

  • Steer mid-run

    Write to the lead or to one agent while it works. Your message lands at its next step, or at once if you say so.

    Steering

  • Automations

    A stored prompt that runs on a schedule, from a webhook, or with Run now. Each run becomes work the lead starts on its own.

    Automations

  • Skills and MCP servers

    SKILL.md workflows from the repo, the project or the whole hub, and more tools for agents over MCP, for every project or one.

    Skills

  • Memory

    When you correct the lead or state a rule, it remembers, for you everywhere or for one project. Read, edit or delete it in Settings.

    Memory

  • Usage limits

    An agent that hits a Claude usage limit pauses and carries on by itself at the reset. A machine near the end of its usage window takes no new agents until it has room.

    Machines

Get started

A hub on one machine, and any machines you reach over SSH to run agents. The outputs below are real; the tailnet name and address are placeholders.

  1. Run the install line

    It installs fleetd and starts fleetd init, which walks you through the hub, its claude and gh logins and the desktop app’s pairing. Run it again any time; it keeps what’s done.

  2. fleetd machine add

    Turns a machine you can reach over SSH into one that runs agents. --dry-run prints the plan and runs nothing.

    fleetd machine add --dry-run output 
    $ fleetd machine add builder-1 --dry-run
dry run: nothing runs. Planned for a fresh Linux machine at builder-1 (home /home/demo); a real run first reads the machine's state and leaves out what is already done:
[probe] read the machine's state (read-only)
[1/5] create fleetd's directories
[2/5] install fleetd 0.0.0
[3/5] write the node service
[4/5] enroll the node with a one-time token (sent on stdin)
[5/5] (re)start the node
[hub] wait until builder-1 is online
[exit 0]

  3. Add a project and tell its lead what you want

    In the app, click Add next to Projects and paste a GitHub URL. Then write to the lead as you would to an engineer.
