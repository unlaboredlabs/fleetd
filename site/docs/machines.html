Machines

You’ll add workers, the machines that run agents, and keep them healthy. Run every command on this page on the hub unless it says otherwise.

A worker needs the claude CLI, and for now the same OS and CPU as the hub.

Pick how to add it

Section titled “Pick how to add it”
The machine is Use
Reachable from the hub over SSH fleetd machine add <ssh-host>
The hub machine itself fleetd machine add --local
Behind NAT, or has no SSH from the hub (a laptop) fleetd pair --worker <name>

    It copies the hub’s own fleetd to the machine, enrolls its node, runs the node as a user service, and waits until the machine is online. It prints each remote command before it runs it.

The host name can be anything in ~/.ssh/config or on your tailnet. You can also run fleetd init again and pick the machine from a list.

It is safe to run again: a real run reads the machine’s state first and skips what is done.

Add the hub machine

Section titled “Add the hub machine”

The same steps, run on this machine without SSH. fleetd init does this when you pick “(this machine)”. Run it again to repair the hub machine’s node.

Log in Claude on a worker

Section titled “Log in Claude on a worker”

Sessions use the worker’s own claude setup in ~/.claude. If claude works in your shell there, it works for fleetd: your login, a proxy in ~/.claude/settings.json, and your MCP servers.

If it isn’t logged in, log in on the worker as you normally do:

Behind a proxy, log in through your proxy instead. To give a worker’s sessions their own claude profile, see The Claude login.

Disk and load

Section titled “Disk and load”

A machine short of disk or CPU takes no new agents until it has room again. Agents already running keep going.

New agents wait while They start again at
Free space where the worktrees live is below minFreeGb in node.json: 10% of the disk or 20 GB by default, whichever is larger. 10% above it.
The 1-minute load is above twice the machine’s CPUs. 10% below it.

The project’s status says why, for example “Paused new agents: 14 GB free on builder-1”, and fleetd doctor shows each machine’s free space. A writer’s worktree, build output included, goes once its PR merges, unless it holds uncommitted or unpushed work. When sccache is on the node’s PATH, sessions compile through it, so a dependency builds once per machine rather than once per worktree.

Check health

Section titled “Check health”

It checks the hub and every machine: online, claude version and login, commit identity, disk space, sleep when idle, and the usage breaker. Each problem comes with the command that fixes it.

The app’s Machines screen shows the same checks. Every finding and its fix: Troubleshooting.
