    Reference

    CLI reference

    Generated from fleetd help, so it matches the binary this site was built with. Exit codes: 0 ok, 1 failed (a check that did not pass), 2 usage, 3 refused, 4 hub or node unreachable, 78 (listen) the hub refused the key.

    Commands#

    #
    fleetd version
    print the fleetd version and protocol
    #
    fleetd help
    show this message
    #
    fleetd update [--check] [--channel <c>]
    replace this fleetd with the latest release

    Setting up#

    On the hub machine.

    #
    fleetd init [--yes] [--home <dir>] [--listen <host:port>] [--url <url>]
    [--git-identity "Name <email>"] [--no-service] [--unit-suffix <s>]
    set up fleetd step by step in a terminal: the hub on this machine (home default ~/.fleetd/hub, kept running by a systemd or launchd user service), where it listens (your tailnet when there is one), the claude and gh logins, the machines that run agents, a first project and the desktop app, then fleetd doctor. Run it again to check and repair; it keeps what works. --yes takes every default. Without a terminal and without --yes it only sets up the hub. --url is how devices reach the hub (default http://<listen>); --git-identity is the commit author for every machine (the GitHub noreply address for public repos); --no-service prepares everything but leaves starting the hub to you
    #
    fleetd init --join <hub url> --code <code> [--machine-id <id>] [--git-identity "Name <email>"] [--rejoin]
    [--claude-config-dir <dir>]
    make this machine a worker of that hub, without SSH from the hub: the command fleetd pair --worker prints on the hub. Run again, it keeps the node's enrolment and repairs the rest; --rejoin enrols again with a new code
    #
    fleetd doctor [--home <dir>]
    run every setup check on the hub now and print each problem with its fix
    #
    fleetd uninstall [--home <dir>] [--purge]
    stop and remove the hub's service; its data stays unless --purge, which also removes what an older fleetd installed for T3 Code
    #
    fleetd machine add <ssh-host> | --local [--machine-id <id>] [--tags a,b] [--dry-run] [--no-service]
    [--hub-url <url>] [--ssh-config <file>] [--home <hub home>] [--unit-suffix <s>]
    [--claude-config-dir <dir>]
    set up a machine that runs agents, over SSH (--local: this machine): copies this fleetd there, checks its claude (installed, version >=2.1.300, <2.2.0, logged in), enrolls the node and runs it as a user service, then waits until the machine is online; prints every command first, --dry-run only prints (for a fresh machine, without connecting); --no-service enrolls the node but writes no service and prints how to run it; safe to run again
    #
    fleetd machine remove <id> [--purge] [--home <hub home>]
    stop and remove the node's service on the machine and revoke its key on the hub; --purge also deletes ~/.fleetd/node and ~/.fleetd/claude.env there, and what an older fleetd installed for T3 Code
    #
    fleetd pair [--name <device>] [--home <dir>]
    print a one-time code (15 min) that pairs the desktop app with this hub; the app on this machine pairs by itself
    #
    fleetd pair --worker <machine-id> [--home <dir>]
    print the one command that makes another machine a worker of this hub, with a one-time code (15 min): for a machine the hub can't reach over SSH

    Running by hand#

    #
    fleetd hub start [--home <dir>] [--listen <host:port>] [--queue-ttl <seconds>] [--router-model <model>]
    run the hub (default home ~/.fleetd/hub, listen 127.0.0.1:4790, writes to an offline machine wait 24 h, intents without a project are routed by the claude CLI with claude-haiku-5-5)
    #
    fleetd hub key create --name <name> --role <read|operate|admin> --machines <'*'|id,id> [--home <dir>]
    create an agent key for the MCP endpoint; prints the key once
    #
    fleetd hub key create --human --name <device> [--role <role>] [--machines <'*'|id,id>] [--home <dir>]
    a key for a person's device (the desktop app): what it answers is recorded as the human's; role defaults to operate on every machine
    #
    fleetd hub key list [--home <dir>]
    #
    fleetd hub key revoke <keyId> [--home <dir>]
    takes effect at once, also on a running hub
    #
    fleetd hub token create --machine <id> [--home <dir>]
    print a one-time enrollment token (15 min) for fleetd node join
    #
    fleetd node join --hub <url> (--token <token> | --token-file <file|->) --machine <id> [--tags a,b]
    [--name <name>] [--home <dir>] [--enroll-only] [--claude-config-dir <dir>]
    enroll this machine with the hub, then keep its link up (node home default ~/.fleetd/node); --token-file - reads the token from stdin; --enroll-only exits once the hub has accepted this node; sessions use your own claude setup (~/.claude) unless --claude-config-dir names a dedicated one
    #
    fleetd node run [--home <dir>]
    keep the link up for a machine that has joined
    #
    fleetd listen --hub <url> --key-file <path> (--exec '<cmd>' | --post <url>)
    [--types a,b] [--machines a,b] [--name <name>]
    deliver hub events, at least once and in order, to a command (one event's JSON on stdin) or a URL; the cursor lives in ~/.fleetd/listen/<name>.cursor (name default "default"). Exits 78 when the hub refuses the key.
    #
    fleetd retro run --hub <url> --key-file <path> [--window 14d] [--advise]
    run the retro now: one claude -p turn over the window's incidents (1-28 days) proposes playbook changes; --advise only suggests them
    #
    fleetd prompts list [--project <machine>/<project>] [--home <dir>]
    every prompt fleetd sends a model, which text is in effect, and "update" where a release changed the default you edited
    #
    fleetd prompts show <id> [--project <machine>/<project>] [--default] [--home <dir>]
    #
    fleetd prompts show --session <machine>/<thread> [--home <dir>]
    the text in effect (or the shipped one), or exactly what a session was told
    #
    fleetd prompts edit <id> [--project <machine>/<project>] [--home <dir>]
    edit it in $VISUAL or $EDITOR; warns when a placeholder or a safety rule is gone
    #
    fleetd prompts reset <id> [--project <machine>/<project>] [--home <dir>]
    #
    fleetd prompts diff <id> [--project <machine>/<project>] [--home <dir>]
    shipped vs yours; after a release changed it, what changed in each
    #
    fleetd instructions show|edit [--project <machine>/<project>] [--home <dir>]
    your custom instructions, appended to every lead and task

    Lead-side commands#

    Run by a lead or task inside a project workspace.

    #
    fleetd brief create --workstream <W> (--json '<Brief>' | --file <path>) [--amend <A>]
    freeze the brief of a draft workstream and start it
    #
    fleetd ask --key <k> --class <product|money|credential|irreversible> --text <t> --rec <r>
    [--options a,b] [--blocks "<step>"] [--proceeded] [--workstream <W>]
    #
    fleetd ask --kind do --key <k> --class <c> --text <t> --step '<json>' [--step '<json>' ...]
    [--verify '<check json>']
    a step is {"text","where":"<machine>|browser","command"?,"expect"?}; --verify is a cmd or http check fleetd runs once the human ticks it done (a failure reopens it) ask the human; answers already in the decision log come back at once
    #
    fleetd ask --kind secret --key <k> --sink env:<machine>:<path>|file:<machine>:<path> [--env-name <N>]
    --text <t> [--class credential]
    the human enters it in the desktop app, sealed to that machine; an env: sink writes the line <N>=<value> (N defaults to the key uppercased, . and - as _). You get its fingerprint, never the value
    #
    fleetd gated run --class irreversible|money|credential --argv '<json array>' --reason <r> [--cwd <abs>]
    [--secret-env NAME=<secret key> ...] [--timeout <sec>] [--workstream <W>]
    a command the node runs exactly as stored, in the project workspace by default, only after a human approves it; secrets come from the node's own sinks. The result arrives in a wake
    #
    fleetd ask withdraw <A> [--use <D>]
    #
    fleetd decide --key <k> --value <v> [--why <w>] [--scope project|workstream] [--workstream <W>]
    log a decision you made yourself
    #
    fleetd status set "<one line>" [--workstream <W>]
    #
    fleetd decisions search "<query>"
    #
    fleetd task spawn --workstream <W> --title <t> --prompt <p> [--kind write|read|review] [--areas a,b]
    [--model <m>] [--effort low|medium|high|max] [--tier S|M|L] [--estimate <min>]
    [--serves done:<n>|issue:<ref>|defect:<text>|ask:<A>] [--pr <url>] [--qa]
    delegate work to a subagent; writers need --areas and --serves and get their own branch; a review task needs --pr, and --qa marks it a QA run
    #
    fleetd task list [--state <s>] [--workstream <W>]
    #
    fleetd task status <T>
    #
    fleetd task message <T> "<text>"
    steer a running task, answer a waiting one, or continue an ended one
    #
    fleetd task cancel <T> [--reason <r>]
    #
    fleetd claim done --workstream <W>
    fleetd runs the workstream's done-when checks itself; only all of them passing makes it done (exit 1 when a check did not pass)
    #
    fleetd review verdict --task <T> --sha <full head SHA> --blocking <n> --non-blocking <n> --summary "<s>"
    [--baseline <n> --candidate <n>]
    the last step of a review task; a research judge also reports its metric for the baseline and the candidate, and fleetd computes GO, STOP or INCONCLUSIVE
    #
    fleetd change enqueue --pr <url> [--task <T>] [--workstream <W>] [--serves <s>] [--tier S|M|L]
    put a PR on its repo's merge train (a write task's PR goes on by itself); its body needs a 'Source: <serves>' line. Only the train merges.
    #
    fleetd change status <X>
    #
    fleetd inventory
    the project's open work ranked: failing checks, open issues (gh), open asks and TODO/FIXME markers; with nothing left that has a value source and no open child, the project's finish-all workstream goes idle
    #
    fleetd workstream spawn --text "<intent>" --serves issue:<#n|url>|defect:<text>|done:<n>
    [--template bugfix|feature|research]
    a finish-all lead starts a child workstream for one item with a value source

    lead-side commands reach the hub through the local node (FLEETD_NODE_SOCK, default ~/.fleetd/node/node.sock); exit 0 ok, 1 checks failed, 2 usage, 3 refused, 4 hub unreachable
