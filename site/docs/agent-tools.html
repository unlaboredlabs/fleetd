    Agent tools

    Generated from fleetd's source by cargo run -p docsgen, so it matches the code. Don't edit this file by hand: CI fails when it differs from the generator's output.

    Every agent fleetd starts is a Claude Code session. fleetd adds its own MCP server, named fleetd, with the tools for the agent's role. Claude Code shows them as mcp__fleetd__<tool>. Each call goes to the hub, which checks it whatever the prompt says.

    Roles#

    The app shows each agent's role on its lane. The role decides the fleetd tools; every session gets the same Claude Code tools.

    RoleHow it startsfleetd toolsCan start agents
    LeadOne per project, started by the project's first orderLead toolsYes
    Finish-all leadA lead whose workstream runs the finish-all playbook. It also uses inventory and workstream_spawnLead toolsYes, child workstreams too
    Implementerspawn_agent with kind write. Gets its own worktree and branchTask toolsNo
    Readerspawn_agent with kind readTask toolsNo
    Reviewerspawn_agent with kind reviewTask toolsNo
    VerifierA review task the review gate starts as the verifierTask toolsNo
    QAspawn_agent with kind review and qa: trueTask toolsNo
    RouterOne claude -p on the hub that reads each new order; not a sessionNone, no MCP serversNo

    The router's Claude Code tools: none. fleetd starts it with --tools "", --strict-mcp-config and --safe-mode.

    Hub limits#

    The hub checks these on every fleetd call a session makes, through its MCP tools or a fleetd command in its shell. A refusal says why and what to do instead.

    LimitValue
    Who can start agentsA lead, with spawn_agent, workstream_spawn. A task's agent can't.
    Depth1. A lead is depth 0 and its tasks depth 1; nothing goes deeper.
    Open tasks per lead32 (queued, running or idle). Slots cap what runs at once.
    Calls a task's agent may makereport, ask_lead, claim_done. Every other call is refused.
    Finish-all children open at once5 by default; the policy file's finishAll.maxChildren changes it.
    What a child workstream may serveissue, defect, done. Never invented work.
    Gated commands (gated_run)Classes irreversible, money, credential. Run only after a human approves; at most 1800 s.
    What a lead may ask the human (ask)Classes product, money, credential, irreversible. Anything else it decides itself (decide).

    These limits cover calls to fleetd, not what the agent's own shell can do. A task runs with full Bash, so gated_run is not the only way it could run a command. A process that leaves its session's process tree (for example with setsid) and scrubs its environment counts as you, with no limits: see "Known limit" on the Security page. Run agents you don't trust as a different OS user.

    spawn_agent#

    Start a fleetd agent (a task) with its own session, slot and lane. kind write|read|review; a writer needs areas from the project's policy and serves (done:<n>, issue:<ref>, defect:<text> or ask:<id>) and gets its own worktree and branch; a review task needs pr. model and effort are optional. A busy area or a full slot board queues it and it starts by itself. Its result arrives in a later wake: end your turn instead of waiting.

    ParameterTypeRequiredDescription
    areasstring[]noAt most 20 items.
    effortstringnoOne of low, medium, high, max.
    estimateMinutesnumbernoOlder leads only: fleetd no longer asks for time estimates and the CLI no longer sends one.
    itemstringnoThe plan item this task works on; refused when it belongs to another order.
    kindstringnoOnly write tasks get a worktree and leases. One of write, read, review. Default "write".
    modelstringno
    prstringno
    promptstringyesAt most 8000 characters.
    qabooleanno
    servesstringno
    tierstringnoOne of S, M, L.
    titlestringyesOne line. At most 80 characters.
    workstreamIdstringyesW<n>, e.g. W1.

    Who may call: a lead, checked by the hub. Needs a human: no.

    {
  "name": "spawn_agent",
  "arguments": {
    "areas": [
      "api"
    ],
    "kind": "write",
    "prompt": "Limit uploads to 10 a minute per API key. Over the limit, answer 429 with Retry-After.",
    "serves": "done:0",
    "title": "Rate-limit the upload API",
    "workstreamId": "W3"
  }
}

    ask#

    Ask the human about product, money, credentials or irreversible actions only, with a dotted decision key and your recommendation. kind do: steps a human performs; kind secret: a value sealed to a machine (you only see its fingerprint). Never block on it: carry on (proceededOnRec) or with other work. The answer arrives in a later wake.

    ParameterTypeRequiredDescription
    blocksstringnoAt most 200 characters. Default "nothing".
    classstringyesAny string: the hub refuses classes outside AskClass with the "decide this yourself" fix text.
    contextstringnoAt most 400 characters.
    envNamestringnoAn env: sink's variable, when the key's own name (secret_env_name) is not wanted or valid.
    keystringyesLowercase dotted slug, [a-z0-9]+(.[a-z0-9_-]+)*, at most 80.
    kindstringnoOne of decide, do, secret. Default "decide".
    optionsobject[]noAt most 6 items.
    options[].consequencestringnoOne line, what happens if the human picks it. Absent only on asks stored before labels. At most 200 characters.
    options[].keystringyesThe decision value recorded when the human picks it, e.g. "public-snapshot". At most 2000 characters.
    options[].labelstringnoA few words, e.g. "Public snapshot". Absent only on asks stored before labels: show humanize_key. At most 80 characters.
    proceededOnRecbooleannoDefault false.
    recommendationstringnoThe key of one of options. At most 2000 characters.
    recommendationWhystringnoOne line. At most 200 characters.
    sinkstringnoRequired for secret; the ask's key names the secret.
    stepsobject[]noAt most 20 items.
    steps[].commandstringno
    steps[].expectstringnoWhat the human should see when the step worked. At most 500 characters.
    steps[].textstringyesAt most 500 characters.
    steps[].wherestringyesA machineId or "browser".
    textstringyesThe question, one short line. At most 500 characters.
    verifyobjectnoDo only. One of these shapes: {pr, repo, type}; {ref, repo, type}; {contains, status, type, url}; {argv, expectExit, machineId, type}; {repo, testId, type}; {criteria, type}; {question, type}.

    Claude Code tools#

    The same for every session. The router gets none. Listed for Claude Code 2.1.302, the version fleetd is tested with.

    Allowed: Bash, DesignSync, Edit, NotebookEdit, Read, ReportFindings, Skill, ToolSearch, WebFetch, WebSearch, Write.

    A project's policy file can deny more with tools.deny. In a run started approval-required, Claude Code asks before it uses a tool and the question comes to you; tools.allow answers it ahead of time.

    Blocked, in --disallowedTools and in the permissions.deny of fleetd's settings, so your own settings can't turn them back on:

    ToolWhy
    Task, Agentfleetd manages agents (spawn_agent). Task and Agent are one tool: init lists Task, the model sees Agent, and denying either removes both.
    Workflow, ListAgents, SendMessage, TaskStop, TaskOutput, TeamCreate, TeamDeletefleetd manages agents. Every agent is a fleetd task with its own session, slot, worktree, lane, steering and receipts, started with spawn_agent.
    AskUserQuestion, EnterPlanMode, ExitPlanModeNobody sits at a terminal to answer it, so the run would stall. Agents use ask or ask_lead.
    CronCreate, CronDelete, CronList, ScheduleWakeupfleetd schedules work (tasks, wakes), never inside one claude process the node may restart.
    EnterWorktree, ExitWorktreefleetd owns worktrees, one per writer. A session that moves its own folder can't be resumed.

    fleetd also blocks any tool like these that a newer Claude Code adds: it reads the installed claude's tool list when it checks the machine, and a session that still offers one fails the check.

    Settings fleetd forces#

    Set in the claude process's environment. "In settings" marks the ones also in fleetd's settings file for a session, which outranks the env in your own settings.

    VariableValueWhereIn settingsWhy
    CLAUDE_CODE_DISABLE_BACKGROUND_TASKS1Every claude fleetd startsyesTakes run_in_background out of Bash and Agent and refuses it: a background job outlives the turn fleetd tracks.
    CLAUDE_CODE_DISABLE_WORKFLOWS1Every claude fleetd startsyesRemoves the Workflow tool: fleetd manages agents.
    CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS1Every claude fleetd startsyesRemoves the built-in Explore and Plan agents: fleetd manages agents.
    CLAUDE_CODE_DISABLE_AGENT_VIEW1Every claude fleetd startsyesRemoves the built-in claude agent: fleetd manages agents.
    CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMSremovedEvery claude fleetd startsyesAgent teams: fleetd manages agents.
    CLAUDE_CODE_COORDINATOR_MODEremovedEvery claude fleetd startsyesCoordinator mode turns a session into one that only delegates (its tools become Task, ListAgents, SendMessage, TaskStop, Workflow).
    CLAUDE_CODE_DISABLE_AUTO_MEMORY1, and autoMemoryEnabled: falseEvery claude fleetd startsyesfleetd owns an agent's context (briefs, decisions, instructions). Notes claude keeps per folder would carry stale, unreviewed text from one agent's worktree to the next. A project opts back in with claude.autoMemory: true in its policy file.
    DISABLE_AUTOUPDATER1SessionsyesKeeps the claude fleetd checked. An update mid-run would swap the binary under a live session.
    CLAUDE_CODE_STARTUP_FAILURE_RESULTS1SessionsnoA refusal at startup arrives as a result fleetd can read, not only as stderr.
    CLAUDECODE, CLAUDE_CODE_ENTRYPOINT, CLAUDE_CODE_SSE_PORTremovedSessionsnoclaude sets it for its own children and treats a process that has it as nested inside another session.

    What your own setup adds#

    fleetd starts sessions with your own Claude Code setup underneath. The router is the exception: it runs in safe mode with none of it (see Roles).

    Your setupIn a session
    MCP servers (user, project, local)Loaded. fleetd adds its fleetd server next to them.
    Skills, plugins, hooks, CLAUDE.mdLoaded as in your own claude.
    Allow and deny rulesApplied. fleetd's blocked tools stay blocked: its settings outrank yours.
    Your own agents (~/.claude/agents)Listed, but nothing can start them: the Agent tool is blocked.
    Env in your settingsApplied, except the switches above, which fleetd sets last.

    A project's policy file can add rules for its sessions: tools.allow and tools.deny (Claude Code rule syntax), and claude.autoMemory: true.
