    Using fleetd

    What agents are told

    Every word fleetd sends a model is listed on this page, in the app's Settings → Prompts and in fleetd prompts list, and you can edit each one. A session keeps the text it started with.

    How a session gets its instructions#

    There is no hidden system prompt. fleetd's instructions are the first message of a session (lead, task, reviewer, judge), later messages into it (wakes, review findings, train news, nudges), or the input of a one-shot claude -p with no tools (the router, the retro). Your own claude setup applies as usual underneath (Config & files). Every prompt is listed at the end of this page.

    Claude's auto memory is off#

    Claude Code can keep its own notes per folder ("auto memory") and read them back in later sessions. fleetd turns that off in every claude it starts, whatever your ~/.claude/settings.json says: what an agent knows comes from its brief, the decisions and your instructions, all of which you can read here, not from notes another agent left behind in a worktree. fleetd doctor shows "claude auto memory off" for each machine once a session has run there. A project turns it back on for its sessions with claude: { autoMemory: true } in its policy file.

    Safety rules: code or prompt#

    Most rules don't depend on the prompt. fleetd enforces them in code whatever the text says: secrets are sealed to a machine, gated commands wait for your tap, only the train merges, and done is decided by the hub running the checks. Editing those words away only means agents hit refusals they weren't warned about.

    Some rules live only in the prompt, marked "prompt only" in the table below: the lead never writes code, reviewers don't read the PR description, a lead doesn't re-ask a decided question and asks you only about product, money, credentials or something irreversible. Remove one and nothing else stops it.

    Edit a prompt#

    In the app: Settings → Prompts. Pick Hub-wide or a project in "Texts for", open a prompt, edit it and Save; "Compare with default" shows your changes, "Reset to default" drops them. Click a placeholder to insert it. Warnings show as you type and never stop a save.

    On the hub machine:

    fleetd prompts show lead.start
fleetd prompts edit lead.start
fleetd prompts edit task.brief.write --project builder-1/app
fleetd prompts diff lead.start
fleetd prompts reset lead.start

    edit opens $VISUAL or $EDITOR, prints the warnings and asks Save? [Y/n]. diff shows fleetd's text against yours; show --default prints fleetd's. A project's version beats the global one, which beats fleetd's; one-shots and playbooks have only the global level. Your versions are files under ~/.fleetd/hub/prompts/ (Config & files); change them with fleetd prompts edit, not by hand. From an MCP client: prompts_list, prompt_get, prompt_set (with dryRun to see the warnings only) and prompt_reset.

    Prompts fill in {{name}} placeholders, such as {{project}}. Nothing else is template syntax.

    Warnings#

    Saving never refuses text that isn't empty, but it warns:

    WarningMeans
    a required placeholder is missingthat value no longer reaches the agent (for task.brief.write without {{serves}}, the PR's Source: line)
    unknown placeholder{{name}} isn't one this prompt fills; it is sent as written
    a safety rule is missingits wording is gone; the warning says whether fleetd still enforces it in code or nothing does
    too longover three times the length of fleetd's text

    Your own instructions#

    In the app: Settings → Instructions, for every project or one project. On the hub machine:

    fleetd instructions edit
fleetd instructions edit --project builder-1/app
fleetd instructions show

    They are added to every lead's first message and every task brief (writers, reviewers and judges), global first, under "Custom instructions from the human". Not to the router, the retro or wakes.

    When fleetd changes a default you edited#

    Your version stays in use. In Settings → Prompts the prompt gets a warning dot and "fleetd's default changed since you edited this. Your text stays in effect until you save it again." "Review the update" shows what fleetd changed and what you changed, above both merged: Save merged, Keep mine, or Use the new default. On the hub machine, fleetd prompts list marks it update, fleetd prompts diff <id> shows both changes and edit opens the merge. A safety rule the new default added and your text lacks shows as a warning.

    Playbooks are the exception: an edited playbook gets no notice when fleetd's version changes. After an update, compare it with fleetd prompts diff playbook.<name>.

    What a running agent keeps#

    Each session keeps the exact prompt versions it started with, wakes included. An edit reaches new sessions at once: a task at its next attempt, a lead at its next start. To give a running lead your edit now, restart it with lead_restart from an MCP client (Its lead).

    See exactly what an agent was told#

    In an order, "Show full prompt" on an agent's lane or in the lead's header opens the exact first message that session was sent, which version of each prompt it used (fleetd's, your hub-wide edit, the project's, your instructions) and the tools it never gets. On the hub machine, the message alone:

    fleetd prompts show --session <machine>/<thread>

    session_prompt_get returns the same to an MCP client. Later messages are in the lead's conversation.

    Not editable: tool descriptions and CLI replies#

    MCP tool descriptions and what the lead-side CLI prints back (each next: and fix:) are the other half of a protocol with code: a description must match its tool, a next: must name a real command. See the CLI reference and the order tools.
