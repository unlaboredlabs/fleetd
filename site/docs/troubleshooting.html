    Troubleshooting

    fleetd doctor on the hub checks the hub and every machine, and prints each problem with its fix. The app's Machines screen shows the same checks. Fix commands run on the machine the finding names. Each section here is one check: a hub check hub/<name> is #hub-<name>, a machine check <machine>/<name> is #<name>.

    $ fleetd doctor
✗ doctor hub: gh is not logged in on the hub; the merge train and PR checks need it. Fix: gh auth login
✗ doctor hub: claude on the hub is not logged in; the intake router and the retro can't reach a model. Fix: claude auth login
! doctor laptop: laptop is degraded: claude is not logged in for fleetd. Fix: CLAUDE_CONFIG_DIR=~/.fleetd/claude claude auth login (or run `claude setup-token` and put CLAUDE_CODE_OAUTH_TOKEN=<token> in ~/.fleetd/claude.env). Fix: systemctl --user restart fleetd-node.service
✗ doctor laptop: fleetd's Claude on laptop is not logged in, so its sessions can't start. Fix: CLAUDE_CONFIG_DIR=~/.fleetd/claude claude auth login
✗ doctor laptop: No git commit identity is set on laptop. Fix: fleetd pair --worker laptop, then run what it prints on laptop
✓ doctor: 7 of 12 checks pass
[exit 1]

    ✗ is a failure; ! is a warning or a check that couldn't tell.

    The hub doesn't answer#

    $ fleetd doctor
✗ doctor: the hub does not answer at 127.0.0.1:4778: error sending request for url (http://127.0.0.1:4778/mcp): client error (Connect): tcp connect error: Connection refused (os error 111). Fix: fleetd init (it starts the hub and repairs its setup)
[exit 4]

    Run fleetd init. If you run the hub yourself (--no-service), start it with fleetd hub start. The log is ~/.fleetd/hub/hub.log.

    The hub doesn't answer at its own address#

    The hub does not answer at its own address http://…/healthz (…).

    Restart the hub service:

    systemctl --user restart fleetd-hub.service                  # Linux
launchctl kickstart -k gui/$(id -u)/sh.fleetd.hub            # macOS

    gh is not installed or not logged in#

    gh is not logged in on the hub; the merge train and PR checks need it.

    gh auth login

    If gh is missing, install it from cli.github.com first.

    claude on the hub is not logged in#

    claude on the hub is not logged in; the intake router and the retro can't reach a model.

    claude auth login

    For a gateway or API key instead, put ANTHROPIC_BASE_URL and ANTHROPIC_AUTH_TOKEN (or ANTHROPIC_API_KEY) in ~/.fleetd/claude.env and restart the hub service: see claude.env. If claude is missing ("Claude Code (claude) is not on the hub's PATH"), install it first (next section).

    claude on the hub is missing or the wrong version#

    Same findings and fixes as a worker's claude version, for the hub's own claude. Not installed:

    curl -fsSL https://claude.ai/install.sh | bash

    The hub isn't reachable over HTTPS#

    The hub's address http://… is not HTTPS; keys from the desktop app and other machines would cross the network unencrypted.

    Plain HTTP passes on loopback and on a tailnet address (100.64.0.0/10 or a *.ts.net name). Elsewhere, serve the hub over HTTPS, then stop the hub and point fleetd at the new address:

    tailscale serve --bg 4790
fleetd init --url https://<that address>

    The same fix applies to "The hub has no address set up" and to an unreadable ~/.fleetd/hub/setup.json. When the HTTPS address stops answering, check where it points with tailscale serve status.

    A machine is offline or degraded#

    laptop is offline (last seen …). · laptop is degraded: ….

    Restart its node, on that machine:

    systemctl --user restart fleetd-node.service                 # Linux
launchctl kickstart -k gui/$(id -u)/sh.fleetd.node           # macOS

    A degraded reason that names its own fix (such as a claude login) comes first: apply that fix. The log is ~/.fleetd/logs/node.log.

    claude is missing or the wrong version#

    fleetd speaks claude's stream-json protocol, which isn't a stable API, so it runs only claude >=2.1.300, <2.2.0 and was tested with 2.1.302.

    FindingStatusFix
    claude is not installed on laptop; its sessions can't start.✗curl -fsSL https://claude.ai/install.sh | bash
    claude 2.1.250 is older than this fleetd supports (>=2.1.300, <2.2.0).✗claude update (or claude install 2.1.302)
    claude 2.2.0 is newer than this fleetd supports (>=2.1.300, <2.2.0); its stream-json protocol may have changed.✗claude install 2.1.302, or fleetd update
    claude 2.1.303 is newer than 2.1.302, the version this fleetd was tested with. It is inside the supported range, so sessions run.!claude install 2.1.302
    claude --version printed "…", which fleetd can't read as a version.✗curl -fsSL https://claude.ai/install.sh | bash -s 2.1.302

    Sessions on that machine are refused until a ✗ is fixed. fleetd turns claude's auto-updater off for its own sessions.

    fleetd's Claude is not logged in#

    fleetd's Claude on laptop is not logged in, so its sessions can't start.

    On that machine:

    CLAUDE_CONFIG_DIR=~/.fleetd/claude claude auth login

    Or run claude setup-token and put CLAUDE_CODE_OAUTH_TOKEN=<token> in ~/.fleetd/claude.env. A login that expires mid-run ("claude refused fleetd's login: …") has the same fix. See the Claude login.

    claude doesn't answer the protocol probe#

    claude on laptop did not answer fleetd's protocol probe as expected.

    Put the tested claude on that machine:

    claude install 2.1.302

    "claude --version and the running claude disagree (… vs …): two installs on PATH?" means two claudes; reinstall with curl -fsSL https://claude.ai/install.sh | bash and remove the other. "has not probed its claude yet" clears by itself a second after the node starts.

    No or the wrong commit identity#

    No git commit identity is set on laptop. · Commits on laptop use … (from git's global config); the hub's identity is ….

    For a machine set up over SSH, write the hub's identity into its service again, from the hub:

    fleetd machine add laptop

    For the hub's own machine, the finding prints fleetd machine add localhost; run fleetd machine add --local instead.

    For one that joined with a code, run fleetd pair --worker laptop on the hub, then the command it prints on the machine. Without a hub identity, set one on the machine: git config --global user.email '<id>+<user>@users.noreply.github.com'.

    Low disk space#

    … free under ~ on laptop; fleetd needs at least 5.0 GB.

    Each writer session gets its own git worktree, so a machine needs room. Free space under the path the finding names; df -h <path> shows what is left.

    The usage breaker is open#

    New turns on laptop are paused by the usage breaker.

    The machine's Claude login hit a plan or rate limit, and new turns wait. Wait for the reset (the finding says when), or, once the login has capacity, call usage_resume for that machine from an MCP client.
