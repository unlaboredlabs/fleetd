Set up fleetd on one machine and give a bot its first piece of work.

You need a Mac (macOS 13 or newer) or a Linux x64 machine that stays on, and a GitHub repo to work on.

<Steps>

1. **Install fleetd and run the wizard.**

   On the machine that will run the hub:

   ```sh
   curl -fsSL https://fleetd.sh | sh
   ```

   The wizard, `fleetd init`, starts by itself. On a machine with the desktop app it offers to go on in the app
   instead. Press Enter to take each default. It sets up:

   - where the hub listens: your tailnet, your network, or this machine only;
   - the hub as a background service;
   - which machines run agents (this one can);
   - your first bot, from a repo;
   - a pairing code for the app.

   It ends with a summary like this:

   ```text
   ◇  fleetd is ready ─────────────────────────────────────╮
   │                                                       │
   │  hub       http://hub.your-tailnet.ts.net:4790        │
   │  workers   homeserver                                 │
   │  bot       ~/src/hello on homeserver                  │
   │  app       code K4QW-7RNP                             │
   ├───────────────────────────────────────────────────────╯
   ```

   A line with ✗ ends with the command that fixes it. You can run `fleetd init` again at any time.

2. **Open the desktop app.**

   On the hub's machine, the app pairs by itself. On another computer, install with `--no-init` and open the app:

   ```sh
   curl -fsSL https://fleetd.sh | sh -s -- --no-init
   ```

   Enter the hub's address and the pairing code. A code works once, for 15 minutes; `fleetd pair` on the hub prints a
   new one.

3. **Finish setup.**

   The app opens on the setup steps that are left (below). Claude and GitHub are the ones you need before the first
   pull request.

4. **Write to your bot.**

   Click the bot in the sidebar and tell its lead what you want:

   ```text
   fix the typo in the README
   ```

   The lead answers and starts agents. Pull requests and merges show up in the chat as they happen.

5. **Answer its questions.**

   The lead asks only about real choices, as numbered items with a recommendation each. A short reply such as
   `1 go, 2 rec` is enough.

</Steps>

## Setup steps {#setup-steps}

The same steps are in the terminal (`fleetd init --step <id>`) and in the app (Settings › Hub › Setup). Each shows
what to paste and where, then a **Test** button. `fleetd doctor` lists the ones still open.

| Step | Id | Needed |
|---|---|---|
| Where the hub listens | `address` | Yes |
| Where agents run | `machines` | Yes |
| Claude | `claude` | Yes |
| GitHub | `github` | Before the first pull request |
| Import from 1Password | `onepassword` | Optional |
| Invite people | `people` | Optional |
| A Mac for agents | `mac` | Optional |

- **Claude**: the hub's API key, your Claude subscription, or each machine's own `claude auth login`.
- **GitHub**: create the hub's GitHub App with one button, then install it on your repos. Each person then connects
  their own GitHub in Settings › Accounts › GitHub, so their pull requests open as them.

## Without the app {#headless}

On a machine with no screen, you can chat from the terminal:

1. Create a key for yourself, in a file only you can read:

   ```sh
   (umask 077; fleetd hub key create --human --name terminal > ~/.fleetd/human.key)
   ```

2. Find your bot's name:

   ```sh
   fleetd project list
   ```

3. Write to its lead and wait for the reply:

   ```sh
   fleetd chat homeserver/hello "fix the typo in the README" --wait --key-file ~/.fleetd/human.key
   ```

`fleetd status` shows how the work is going.
