One command installs fleetd on any Mac or Linux machine:

```sh
curl -fsSL https://fleetd.sh | sh
```

In a terminal, it then starts the setup wizard, `fleetd init`. Go on with the [Quick start](/docs/quick-start).

## Only the Mac app {#mac-app}

To use fleetd cloud, or a workspace that runs on another computer, a Mac needs only the app:

1. [Download for Mac](/download/mac): a disk image.
2. Open it and drag **fleetd** onto **Applications**.
3. Open fleetd from Applications, then sign in or connect to your workspace. See [The desktop app](/docs/desktop-app#pair).

It needs macOS 12 or newer, and updates itself. To run agents or a workspace on this Mac later, run the command above.

## What you need

- **macOS 13 or newer, or Linux x64.** On an older Mac the installer stops and changes nothing.
- **`claude`** on each machine that runs agents. `fleetd init` checks for it and prints the install command.
- **`git`** on the workspace's machine.
- **GitHub**: the workspace's own GitHub App, which you create in setup, or `gh` logged in on the workspace.

You don't need `sudo`, and fleetd doesn't run as root: Claude Code won't run agents as root. Logged in as root on
Linux (most servers' default), the installer offers to make a user named `fleetd` and installs as that user. Without
a terminal it changes nothing and prints the commands to do the same.

## What it installs

- The CLI: `~/.fleetd/bin/fleetd`, linked from `~/.local/bin/fleetd`.
- On a Mac: the desktop app, `~/Applications/fleetd.app`.
- On Linux with a display: the desktop app as an AppImage, with an entry in your app menu.

Every download is checked against the release's checksums. Running the installer again replaces what it installed.
To read the script first, open [fleetd.sh/install.sh](https://fleetd.sh/install.sh).

:::tip
On newer Linux versions such as Ubuntu 24.04, install FUSE 2 so the app starts quickly: `sudo apt install libfuse2t64`.
:::

## Check it

```sh
fleetd version
```

If your shell can't find `fleetd`, add `~/.local/bin` to your `PATH`:

```sh
export PATH="$HOME/.local/bin:$PATH"
```

## Options

Pass options after `sh -s --`, for example:

```sh
curl -fsSL https://fleetd.sh | sh -s -- --no-init
```

- `--no-init`: install, but don't start the setup wizard.
- `--no-app`: install the CLI only.
- `--app`: install the desktop app on Linux even with no display.
- `--join <url>`, with the one-time code in `FLEETD_JOIN_CODE`: join a workspace as a machine instead of running the
  wizard. `fleetd pair --worker` prints this line for you. The code stays out of the command's arguments, which other
  users on the machine can list; `--code <code>` still works. See [Machines](/docs/machines#join).
- `--mac`: with `--join`, join as [the agents' Mac](/docs/agents-mac).
- `--uninstall`: stop and remove fleetd's services on this machine, then the CLI and the app. See
  [Updating & uninstall](/docs/updating-and-uninstall#remove).

## Builds

You install the newest build: a new one comes after each change to fleetd that passes its tests. From then on your workspace
takes builds in stages, at the [update speed](/docs/releases#speed) you pick. See [Builds & rollout](/docs/releases).

## Build from source {#from-source}

With [Bun](https://bun.sh):

```sh
git clone https://github.com/unlaboredlabs/fleetd
cd fleetd/fleetd
bun install --frozen-lockfile
bun run compile
```

The CLI is `fleetd/dist/fleetd`; copy it to `~/.local/bin/fleetd`. To build the desktop app, see
[CONTRIBUTING](https://github.com/unlaboredlabs/fleetd/blob/main/docs/CONTRIBUTING.md).

## A second workspace on one machine {#second-fleet}

To try fleetd next to a workspace you already run on the same machine, don't run the wizard. Follow
[Run a second workspace on one machine](/docs/config-and-files#second-fleet) instead.
