Where fleetd keeps everything, and the settings you can change. The [hub](/docs/glossary#hub) keeps its state under
`~/.fleetd/hub`; each [worker](/docs/glossary#worker)'s [node](/docs/glossary#node) under `~/.fleetd/node`.

## ~/.fleetd {#home}

```text
~/.fleetd/
  bin/fleetd             the CLI (linked from ~/.local/bin/fleetd)
  hub/                   the hub's home (hub machine only)
    hub.sqlite           everything the hub knows, timelines included
    setup.json           what fleetd init and machine add set up: address, commit identity, machines
    hub.log              the hub service's log
    cli.key              the admin key the CLI on this machine uses (an agent key)
    keys/<name>.key      agent keys made with fleetd hub key create --agent
    playbooks/<name>.md  your version of a playbook; delete it to use fleetd's
    prompts/<id>.md      your version of a prompt, hub-wide
    prompts/projects/<key>/<id>.md   the same for one project
  node/                  the node's home (every worker)
    node.json            the node's settings (below)
    node-key.pem         proves the node to the hub
    node-box-key.pem     opens secrets sealed to this machine
    node.sock            the socket lead-side commands use to reach the hub
    sessions.sqlite      the node's sessions, and timings not yet sent to the hub
    worktrees/           one git worktree per writer session
  claude.env             optional extra environment for every claude fleetd starts
  logs/node.log          the node service's log
```

`fleetd uninstall` keeps all of it. See [Updating & uninstall](/docs/updating-and-uninstall).

## Logs {#logs}

| Run as | Hub log | Node log |
|---|---|---|
| A service (`fleetd init`, `fleetd machine add`) | `~/.fleetd/hub/hub.log` | `~/.fleetd/logs/node.log` |
| By hand (`fleetd hub start`, `fleetd node join` or `node run`) | The terminal | The terminal |

## node.json {#node-json}

`~/.fleetd/node/node.json` on each worker. `fleetd node join` and `fleetd machine add` write it. Restart the node
after you change it.

| Key | Means |
|---|---|
| `hub` | The hub's address. |
| `machineId`, `name`, `tags` | How the hub knows this machine. |
| `enrolled` | `true` once the hub accepted the node's key. |
| `cmdRoots` | Folders the node may run commands in, and below. Absent: your home directory. A project's checkout must be inside one: `fleetd project add` refuses one outside, and `fleetd doctor` flags an existing one. |
| `claudeConfigDir` | A dedicated claude profile for this machine's sessions. See [below](#claude-profile). |
| `minFreeGb` | New agents wait while the disk holding the worktrees has less than this many GB free. Absent: 10% of the disk or 20 GB, whichever is larger. `0` turns it off. Read with every heartbeat, no restart needed. See [Disk and load](/docs/machines#guard). |

## The Claude login {#claude}

Sessions run `claude` with your own setup on that machine, `~/.claude`. These all work as they do in your shell:

- your login;
- the `env` in `~/.claude/settings.json`, such as a proxy's `ANTHROPIC_BASE_URL`;
- an `apiKeyHelper`;
- your MCP servers.

`fleetd doctor` shows what each worker uses:

```text
claude 2.1.302, logged in (Max), via proxy http://127.0.0.1:8317 from ~/.claude/settings.json
```

fleetd adds its own settings on top of yours, per session:

| fleetd adds | Why |
|---|---|
| `--mcp-config` | fleetd's agent tools. |
| A `--settings` overlay | Pins claude's version, turns claude's auto memory and its own subagents off ([why](/docs/what-agents-are-told#no-subagents)), and denies tools agents never get: plan mode, worktrees, cron. |

### A dedicated claude profile {#claude-profile}

To give a worker's sessions their own claude profile:

1. Set `"claudeConfigDir": "<dir>"` in `~/.fleetd/node/node.json` on the worker, or join with
   `fleetd node join --claude-config-dir <dir>`.
2. Restart the node.

A session resumes only under the config dir it started in.

## claude.env {#claude-env}

Optional. `KEY=VALUE` lines for every `claude` fleetd runs, for a variable your login needs that the services don't
see. Blank lines, `#` comments and `export ` are allowed. Keep it mode `0600`.

```ini
CLAUDE_CODE_OAUTH_TOKEN=<token from claude setup-token>
# or
ANTHROPIC_BASE_URL=https://gateway.example.com
ANTHROPIC_AUTH_TOKEN=<token>
```

Nodes put every line in each session's environment, re-read at each session start.

The `env` in your `~/.claude/settings.json` outranks it, as it does for your own `claude`.

## .fleetd/policy.yaml {#policy}

An optional file in a project's repo. Commit it to the default branch; changes apply within a minute.

```yaml
tools:
  allow: ["Bash(npm test:*)"]
  deny: ["Bash(git push:*)"]
branchPrefix: team-a/
```

| Key | Default | Does |
|---|---|---|
| `tools.allow`, `tools.deny` | none | Claude permission rules for every session. Deny wins. |
| `branchPrefix` | `fleetd/` | What writer and train branches start with. Must end in `/`. |

A broken file is refused with the exact problem, never ignored, so a typo can't drop a deny rule.

## Services {#services}

`fleetd init` and `fleetd machine add` run the hub and node as user services:

|---|---|

| | systemd unit |
|---|---|

`--unit-suffix <s>` adds a suffix to these names, to run a second fleet's services on one machine. A second fleet
never writes, stops or removes the first one's services.

## Run a second fleet on one machine {#second-fleet}

To try fleetd next to a fleet you already run, give the test fleet its own folder with `FLEETD_HOME` and its own port.
Every command then keeps all its state there and never reads or writes `~/.fleetd`.

1. Set up the test hub's files. Run `export FLEETD_HOME=$HOME/fleetd-test` in each terminal you use for it.

   ```sh
   export FLEETD_HOME=$HOME/fleetd-test
   fleetd init --no-service --listen 127.0.0.1:4797 --url http://127.0.0.1:4797 \
     --git-identity "Your Name <id+you@users.noreply.github.com>" </dev/null
   ```

   With no terminal (`</dev/null`), `init` only writes the hub's setup and the CLI's key, and starts nothing.

2. Start the hub. Keep the terminal open; it logs there.

   ```sh
   fleetd hub start --listen 127.0.0.1:4797
   ```

3. In another terminal, add this machine as a worker of the test hub:

   ```sh
   fleetd pair --worker test-1    # its output has a one-time --code
   fleetd node join --hub http://127.0.0.1:4797 --token <code> --machine test-1
   ```

4. Use the test fleet as you would your own:

   ```sh
   fleetd doctor
   fleetd project add ~/src/sandbox --machine test-1 --yes
   fleetd status
   ```

Stop the hub and node with Ctrl+C. Delete `$FLEETD_HOME` to remove the test fleet. To run it as services instead, add
`--unit-suffix <s>` to `fleetd init` and `fleetd machine add`.

### What FLEETD_HOME covers {#home-scope}

| | Where |
|---|---|
| The hub's home: `init`, `doctor`, `uninstall`, `machine`, `pair`, `project`, `hub`, `prompts`, `instructions`, and `status`, `time`, `steer`, `steers` without `--hub` | `$FLEETD_HOME/hub` |
| The node's home: `node join`, `node run` | `$FLEETD_HOME/node` |
| The app's hand-off from `init` and `pair` | `$FLEETD_HOME/app-pair.json`. Start the desktop app with the same `FLEETD_HOME` to pair with it. |
| Lead-side commands (`claim`, `change`, `plan`, …) | `FLEETD_NODE_SOCK`, else `$FLEETD_HOME/node/node.sock`. Sessions get it set. |

`--home <dir>` names one hub's or node's folder. Without `FLEETD_HOME`, that command keeps everything else in the
folder above it, so `--home $T/hub` works like `FLEETD_HOME=$T`. `FLEETD_HOME` wins when both are given.

## Ports and addresses {#ports}

| | |
|---|---|
| Port | 4790 by default. One port for the app, nodes and MCP clients. |
| Address | Your tailnet address when `fleetd init` finds Tailscale, otherwise `127.0.0.1` only. |
| MCP endpoint | `<hub url>/mcp` |
| Workers | Open no port: their nodes connect out. |

Change it with `fleetd init --listen <host:port> --url <url>`.

## Timelines {#timelines}

The hub keeps the spans behind [Where time went](/docs/time-inspector) in `hub.sqlite`. A span is one stretch of
one agent's work or wait, such as a tool call or a CI check.

| Data | Kept |
|---|---|
| Spans | 30 days (1 to 365 with `fleetd time --retention <days>`) |
| Daily totals and each piece of work's critical path | 400 days |

Each node holds timings it hasn't sent yet in `sessions.sqlite`. While the hub is away, it keeps up to 7 days or
500,000 of them, then drops the oldest; the timeline shows the gap.

## The desktop app {#app}

| | Where |
|---|---|
| Pairing hand-off from `fleetd init` or `fleetd pair` | `~/.config/fleetd/app-pair.json` (macOS: `~/Library/Application Support/fleetd/app-pair.json`), or `$FLEETD_HOME/app-pair.json` for a [second fleet](#second-fleet) |
| Its hub address and key | `desktop-hub.bin` in the same folder, encrypted with the OS keychain or keyring. Without one (no keyring on Linux, or an unsigned or ad-hoc signed Mac build): `desktop-hub.json`, mode `0600`. |
| Its own browser state | `desktop/` in the same folder. |
| Its log | `~/Library/Logs/fleetd/app.log` on macOS, `~/.local/state/fleetd/app.log` on Linux (`$XDG_STATE_HOME/fleetd`), or `$FLEETD_HOME/logs`. Errors only, without keys or message text; crash dumps go in `crashes/` beside it. Help → Reveal Logs opens it. |

## Hub environment {#env}

| Variable | Default | Does |
|---|---|---|
| `FLEETD_STATUS_GITHUB_STALE_SEC` | `180` | Seconds without a good GitHub answer before [Status](/docs/status#stale-data) marks a repo stale. |
| `FLEETD_MAIN_CI_EVERY_SEC` | `60` | How often each merge train checks main's CI. |
| `FLEETD_TRAIN_NO_CI_GRACE_SEC` | `90` | How long a commit may have no check before the train asks whether its PR has CI at all. |
| `FLEETD_TRAIN_BATCH_MAX` | `4` | The most ready PRs the [merge train](/docs/merge-train#batches) merges in one CI run. `1` takes each alone. |
