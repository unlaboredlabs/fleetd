Where fleetd keeps everything, and the settings you can change.

## ~/.fleetd {#home}

```text
~/.fleetd/
  bin/fleetd             the CLI (linked from ~/.local/bin/fleetd)
  hub/                   the hub's home (hub machine only)
    hub.sqlite           everything the hub knows, timelines included
    setup.json           what fleetd init and machine add set up: address, commit identity, machines
    hub.log              the hub service's log
    cli.key              the admin key the CLI on this machine uses
    webhook.key          seals webhook secrets
    playbooks/<name>.md  your version of a playbook; delete it to use fleetd's
    prompts/<id>.md      your version of a prompt, hub-wide
    prompts/projects/<key>/<id>.md   the same for one project
  node/                  the node's home (every worker)
    node.json            the hub it belongs to, its machine id, an optional claudeConfigDir
    node-key.pem         proves the node to the hub
    node-box-key.pem     opens secrets sealed to this machine
    node.sock            the socket lead-side commands use to reach the hub
    sessions.sqlite      the node's sessions, and timings not yet sent to the hub
    worktrees/           one git worktree per writer session
  claude.env             optional extra environment for every claude fleetd starts
  logs/node.log          the node service's log
```

`fleetd uninstall` keeps all of it. See [Updating & uninstall](/docs/updating-and-uninstall).

## The Claude login {#claude}

Sessions run `claude` with your own setup on that machine, `~/.claude`. These all work as they do in your shell:

- your login;
- the `env` in `~/.claude/settings.json`, such as a proxy's `ANTHROPIC_BASE_URL`;
- an `apiKeyHelper`;
- your MCP servers.

`fleetd doctor` shows what each worker uses:

```text
claude 2.1.302, logged in (Max), via proxy http://127.0.0.1:8317 from ~/.claude/settings.json
```

fleetd adds its own settings on top of yours, per session:

| fleetd adds | Why |
|---|---|
| `--mcp-config` | fleetd's agent tools. |
| A `--settings` overlay | Pins claude's version, turns claude's auto memory and its own subagents off ([why](/docs/what-agents-are-told#no-subagents)), and denies tools agents never get: plan mode, worktrees, cron. |

### A dedicated claude profile {#claude-profile}

To give a worker's sessions their own claude profile:

1. Set `"claudeConfigDir": "<dir>"` in `~/.fleetd/node/node.json` on the worker, or join with
   `fleetd node join --claude-config-dir <dir>`.
2. Restart the node.

A session resumes only under the config dir it started in.

The hub's own `claude` (the order router and the retro) uses your normal login on the hub machine, or the gateway
variables in `claude.env`.

## claude.env {#claude-env}

Optional. `KEY=VALUE` lines for every `claude` fleetd runs, for a variable your login needs that the services don't
see. Blank lines, `#` comments and `export ` are allowed. Keep it mode `0600`.

```ini
CLAUDE_CODE_OAUTH_TOKEN=<token from claude setup-token>
# or
ANTHROPIC_BASE_URL=https://gateway.example.com
ANTHROPIC_AUTH_TOKEN=<token>
```

| Reader | Uses |
|---|---|
| Nodes | Every line, in each session's environment. Re-read at each session start. |
| The hub | Only `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY` and `CLAUDE_CODE_OAUTH_TOKEN`. Read when the hub starts, so restart it after a change. |

The `env` in your `~/.claude/settings.json` outranks it, as it does for your own `claude`.

## .fleetd/policy.yaml {#policy}

An optional file in a project's repo. Commit it to the default branch; changes apply within a minute. Without it,
writers may touch the whole repo.

```yaml
areas:
  docs: ["docs/**"]
  app: ["src/**", "package.json"]
defaults:
  model: claude-opus-5-5
  effort: high
finishAll:
  maxChildren: 10
tools:
  allow: ["Bash(npm test:*)"]
  deny: ["Bash(git push:*)"]
lead:
  autoStart: false
claude:
  autoMemory: true
```

| Key | Default | Does |
|---|---|---|
| `areas` | the whole repo | What a writer task may touch. A task leases one or more areas. Names are lowercase slugs. |
| `defaults.model` | `claude-opus-5-5` | The project's task model. |
| `defaults.effort` | `high` | `low`, `medium`, `high` or `max`. |
| `finishAll.maxChildren` | `5` | The most child orders one `finish:` run starts, 1 to 50. |
| `tools.allow`, `tools.deny` | none | Claude permission rules for every session. Deny wins. |
| `lead.autoStart` | `true` | `false`: orders wait for `lead_start` instead of starting the lead. |
| `claude.autoMemory` | `false` | `true`: sessions keep claude's own auto memory. |

A broken file is refused with the exact problem, never ignored, so a typo can't widen what a writer may touch.

## Services {#services}

`fleetd init` and `fleetd machine add` run the hub and node as user services:

<Tabs syncKey="os">
<TabItem label="macOS">

| | launchd file |
|---|---|
| Hub | `~/Library/LaunchAgents/sh.fleetd.hub.plist` |
| Node | `~/Library/LaunchAgents/sh.fleetd.node.plist` |

</TabItem>
<TabItem label="Linux">

| | systemd unit |
|---|---|
| Hub | `~/.config/systemd/user/fleetd-hub.service` |
| Node | `~/.config/systemd/user/fleetd-node.service` |

</TabItem>
</Tabs>

`--unit-suffix <s>` adds a suffix to these names, to run a second fleet on one machine.

## Ports and addresses {#ports}

| | |
|---|---|
| Port | 4790 by default. One port for the app, nodes and MCP clients. |
| Address | Your tailnet address when `fleetd init` finds Tailscale, otherwise `127.0.0.1` only. |
| MCP endpoint | `<hub url>/mcp` |
| Workers | Open no port: their nodes connect out. |

Change it with `fleetd init --listen <host:port> --url <url>`.

## Timelines {#timelines}

The hub keeps the spans behind [Where time went](/docs/time-inspector) in `hub.sqlite`:

| Data | Kept |
|---|---|
| Spans | 30 days (1 to 365 with `fleetd time --retention <days>`) |
| Daily totals and each order's critical path | 400 days |

Each node holds timings it hasn't sent yet in `sessions.sqlite`. While the hub is away, it keeps up to 7 days or
500,000 of them, then drops the oldest; the timeline shows the gap.

## The desktop app {#app}

| | Where |
|---|---|
| Pairing hand-off from `fleetd init` or `fleetd pair` | `~/.config/fleetd/app-pair.json` (macOS: `~/Library/Application Support/fleetd/app-pair.json`) |
| Its hub key | Encrypted with the OS keychain or keyring. Without one (no keyring on Linux, or an unsigned Mac build), a file only you can read (`0600`). |

## Hub environment {#env}

| Variable | Default | Does |
|---|---|---|
| `FLEETD_STATUS_GITHUB_STALE_SEC` | `180` | Seconds without a good GitHub answer before [Status](/docs/status#stale-data) marks a repo stale. |
| `FLEETD_MAIN_CI_EVERY_SEC` | `60` | How often each merge train checks main's CI (every 5 minutes with GitHub webhooks on). |
