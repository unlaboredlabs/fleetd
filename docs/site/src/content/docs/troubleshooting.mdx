title: Troubleshooting
description: Run fleetd doctor, then find what it reported and how to fix it.

Find what's wrong with `fleetd doctor` and fix it.

## Run the doctor {#doctor}

On the workspace:

```sh
fleetd doctor
```

It checks the workspace and every machine. Setup steps still to do come first, then each other problem. Most lines end
with `Fix:` and the command to run, on the machine the line names.

- ✗ a failure: fix it.
- ! a warning.
- – not checked yet, or a step not needed yet.
- ✓ done.

## The workspace {#workspace}

### The workspace doesn't answer

```console capture=doctor-no-hub
$ fleetd doctor
✗  doctor nothing answers at http://127.0.0.1:4778: the workspace isn't running. Fix: fleetd init (it starts the workspace and repairs its setup)
[exit 4]
```

Run `fleetd init`: it starts the workspace and repairs its setup. If it still doesn't answer, [restart the workspace](#restart)
and read its log, `~/.fleetd/hub/hub.log`.

If it says *something else answers*, another program took the workspace's port. Its fix line names the command that shows
which; stop that program, then run `fleetd init`.

### The workspace's address isn't HTTPS

Plain HTTP is fine on this machine and on a tailnet. Anywhere else, serve the workspace over HTTPS. With Tailscale:

```sh
tailscale serve --bg 4790
fleetd init --url https://<that address>
```

### GitHub isn't set up

"gh is not logged in on the workspace" means the workspace has no GitHub App yet and `gh` is logged out. Create the App in
Settings › Workspace › Setup › GitHub (see [GitHub](/docs/github)), or run `gh auth login` on the workspace.

### A key or token failed its test

The workspace's Claude API key, someone's Claude subscription or a 1Password token was revoked, ran out of credit or
expired. Paste it again in the place the line names, then press **Test**.

A line saying a key, subscription or 1Password token "isn't on" a machine means no machine holding it has been online
with that one since it joined or was saved. A machine holding it passes it on by itself once both are online; else save
it again while the machine is online.

## Claude {#claude}

### claude is not logged in

Run `claude auth login` on the machine the line names. Until then, that machine starts no agents.

### claude is missing or the wrong version

fleetd works with the Claude Code versions it was tested with, and moves each machine to that version when fleetd
updates. To fix a missing or broken install:

```sh
curl -fsSL https://claude.ai/install.sh | bash
```

A newer or older version still runs, with a warning. If agents misbehave, install the version `fleetd doctor` names
with `claude install <version>`.

### A key in claude's own settings overrides fleetd

If `~/.claude/settings.json` sets `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN` under `"env"`, it wins over the
Claude account fleetd picks. Move it out of that file, then [restart the node](#restart).

## Machines {#machines}

### A machine is offline

Its node is down, or the machine is asleep or off the network. Wake it, then [restart its node](#restart). The log is
`~/.fleetd/logs/node.log`.

### New agents are paused

A machine stops starting new agents when:

- **Its disk is nearly full.** Free some space; agents start again by themselves.
- **Its Claude login is near a usage limit.** Agents start again once usage drops or the limit resets.
- **Its Claude login hit a rate limit.** Waiting agents go on by themselves at the reset.

Running agents keep going in every case. See [Machines](/docs/machines#guard).

### No git identity on a machine

Commits need an author. Run `fleetd machine add <id>` on the workspace to set it up again, or `fleetd machine add --local`
for the workspace's own machine.

### The service stops when you log out (Linux)

`fleetd doctor` names a one-time `sudo` command that keeps the workspace or node running without a login. Run it once on
that machine. See [Machines](/docs/machines#service-manager).

### The app doesn't open on Linux

"AppImages require FUSE to run" means FUSE 2 is missing. Run `sudo apt install libfuse2t64` (`libfuse2` before
Ubuntu 24.04).

## Keep a machine awake {#sleep}

The node keeps its machine awake while agents run, but not between jobs. To stop sleep on power:

- macOS: `sudo pmset -c sleep 0`
- GNOME: `gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-ac-type 'nothing'`
- KDE Plasma: System Settings › Power Management › On AC Power › When inactive: Do nothing

## Restart a service {#restart}

```sh
fleetd workspace restart    # the workspace, on its machine
fleetd node restart         # a node, on that machine
```

Running agents carry on through either restart.

### Logs

- Workspace: `~/.fleetd/hub/hub.log`
- Node: `~/.fleetd/logs/node.log`
- Desktop app: `~/Library/Logs/fleetd/app.log` on macOS, `~/.local/state/fleetd/app.log` on Linux. **Help › Copy
  Diagnostics** copies what a bug report needs.

## Work is stuck {#stuck}

First, ask the lead in the chat what it's waiting on. Then:

```sh
fleetd status <bot>
```

It shows what each order is doing and why it's blocked.

- **A pull request sits on the merge train**: CI or a review is still running, or it waits for you to merge. See
  [Merge train](/docs/merge-train).
- **Your message waits, and the chat says why**: the lead can't start, usually because `claude` is logged out or its
  machine is offline. See [Claude](#claude) and [Machines](#machines).
- **The lead stopped mid-turn**: fleetd stops a turn that makes no progress for 10 minutes, and the lead tries once
  more by itself. Otherwise it goes on with your next message.
- **"overloaded" in an agent's activity**: Claude's servers were busy. The agent tries again by itself.
